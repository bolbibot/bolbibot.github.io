# Бот-загрузчик видео: дизайн

Дата: 2026-11-14

## Зачем

Отдельный новый Telegram-бот: человек присылает ссылку на видео, бот
отдаёт файл. Это публичный сервис для заработка на широкую аудиторию.
Трафик идёт из Instagram владельца, бот заодно знакомит людей с BolBiBot.

## Цели

- Скачивание по ссылке с YouTube, VK, Rutube, TikTok, Дзен, OK и других
  сайтов, которые поддерживает `yt-dlp`.
- Выбор качества (360p / 720p / 1080p) или только звук (MP3).
- Оплата двумя способами: звёзды Telegram (основной) и рубли через
  Robokassa (второй).
- Упоминание BolBiBot в приветствии и после выдачи файла.
- Запуск одной командой на заграничном VPS через Docker Compose.

## Не цели (первая версия)

- Instagram (нестабилен, нужен аккаунт-донор) — второй этап.
- Рассылки, реферальная программа, реклама в боте.
- Веб-версия, другие языки кроме русского.
- Плейлисты и прямые трансляции — бот отвечает, что не поддерживает.

## Анти-цели

- Списать скачивание за неудачную загрузку.
- Зачислить оплату дважды или зачислить неоплаченное.
- Секреты (токены, пароли Robokassa) в репозитории.
- Хранить чужие видео на сервере после отправки.
- Дать боту ходить по внутренним адресам сервера по присланной ссылке.

## Ограничения

- Репозиторий публичный (GitHub Pages), код бота лежит в папке
  `downloader-bot/` и не влияет на сайт. Секреты только в `.env`,
  которого нет в git.
- Обычный Bot API отдаёт файлы до 50 МБ, поэтому в составе есть свой
  сервер `telegram-bot-api` (лимит 2 ГБ). Для него нужны `api_id` и
  `api_hash` с my.telegram.org.
- Robokassa присылает подтверждение оплаты HTTP-запросом, значит нужен
  домен с HTTPS, направленный на VPS.
- YouTube с российских IP замедлен, а с адресов дата-центров часто
  требует «подтвердите, что вы не бот». Часть роликов Rutube, VK, OK и
  Дзена, наоборот, может не открываться с заграничных адресов.
  Решение исполнителя: прокси задаётся отдельно для каждого сайта
  (`PROXY_DEFAULT` и `PROXY_<САЙТ>`), для YouTube можно подложить файл
  cookies аккаунта-донора. Без них YouTube работает «как получится»;
  блокировка показывается человеку понятным сообщением и не списывается.
- Правила Telegram требуют продавать цифровые услуги в ботах только за
  звёзды. Оплата картой — осознанный риск владельца: бота могут
  ограничить. Поэтому Robokassa включается переменной
  `ROBOKASSA_ENABLED` (по умолчанию выключена), а без неё бот работает
  полностью, и домен с Caddy не нужны.

## Подходы

1. **Один процесс на одном VPS, SQLite, очередь в памяти** (выбран).
   Бот, очередь загрузок и приём уведомлений Robokassa живут в одном
   Python-процессе. Просто запускать и чинить; хватает на тысячи
   скачиваний в день. Минус: при перезапуске задачи в очереди теряются
   (пользователю придёт сообщение повторить, скачивание не списывается).
2. **Бот + отдельные воркеры, Redis, PostgreSQL.** Масштабируется на
   несколько серверов, очередь переживает перезапуск. Для старта
   избыточно: больше частей, дороже сервер, дольше делать.
3. **Готовый внешний API скачивания.** Не нужен свой сервер под
   загрузки, но платим за каждое видео чужому сервису и зависим от него;
   маржа при цене в несколько рублей исчезает.

Владелец проекта отдал выбор техники исполнителю; выбран первый.
Оплата (звёзды + Robokassa) выбрана владельцем.

## Решено владельцем

- Отдельный новый бот, не часть существующего.
- Публичный сервис для заработка.
- Оплата: звёзды Telegram и Robokassa.

## Решения исполнителя (можно поправить)

### Стек

Python 3.12, `aiogram` 3, `yt-dlp`, `ffmpeg`, SQLite через `aiosqlite`,
`aiohttp` для приёма уведомлений Robokassa, Caddy для HTTPS,
Docker Compose. Тесты на `pytest`.

### Как выглядит работа с ботом

```
Человек:  https://rutube.ru/video/abc...
Бот:      «Название ролика» · 12:40
          [360p · 18 МБ] [720p · 54 МБ] [1080p · 120 МБ]
          [Только звук MP3]
Человек:  нажимает 720p
Бот:      Скачиваю… → присылает видео
          «Осталось бесплатных сегодня: 2. Сделано командой BolBiBot»
```

Если лимит исчерпан, вместо загрузки бот показывает тарифы и две
кнопки оплаты: звёздами и картой.

Команды: `/start`, `/help`, `/balance` (остаток и покупка), `/terms`
(условия), для администратора `/stats` и `/refund`.

### Деньги

Единица учёта — «скачивание». Все цены и лимиты лежат в конфиге.

| Что | Звёзды | Рубли |
|-----|--------|-------|
| Бесплатно | 3 в день | — |
| 10 скачиваний | 25 | 49 ₽ |
| 50 скачиваний | 100 | 199 ₽ |
| Безлимит на 30 дней | 150 | 299 ₽ |

- Порядок списания: активный безлимит → бесплатные на сегодня →
  купленные.
- Списание происходит только после успешной отправки файла.
- Бесплатный лимит обнуляется в полночь по Москве.
- Обязательная подписка на канал для бесплатных скачиваний включается
  переменной `REQUIRED_CHANNEL`; пустое значение — выключено.
- Безлимит не продлевается автоматически; повторная покупка добавляет
  30 дней к текущему сроку.

### Оплата

Общий модуль с одной операцией «зачислить оплату по номеру заказа»,
которая выполняется один раз для каждого заказа (повторное уведомление
ничего не меняет).

- **Звёзды:** счёт в валюте `XTR`, ответ на `pre_checkout_query`,
  зачисление по `successful_payment`. `/refund` у администратора
  возвращает звёзды и снимает начисленное.
- **Robokassa:** бот создаёт заказ и даёт кнопку со ссылкой на оплату.
  Robokassa вызывает `POST /robokassa/result`; подпись проверяется
  паролем №2, сумма сверяется с заказом, в ответ `OK<номер>`. После
  зачисления бот пишет человеку. Тестовый режим включается переменной
  окружения. Алгоритм подписи — из настроек магазина, по умолчанию MD5.
  Чеки (фискализация) настраиваются в кабинете Robokassa; в запрос
  передаётся номенклатура, если переменная `ROBOKASSA_RECEIPT` включена.

### Загрузка

- Ссылка проверяется: только `http`/`https`, хост из списка разрешённых
  сайтов (в конфиге, по умолчанию YouTube, VK, Rutube, TikTok, Дзен, OK,
  Twitch-клипы, Vimeo, Dailymotion). Универсальный извлекатель `yt-dlp`
  выключен. Это защита от обращения к внутренним адресам.
- Ограничения: длительность до 3 часов, файл до 2 ГБ, одна задача на
  человека одновременно, глобально 3 загрузки параллельно (всё в
  конфиге). Остальные ждут в очереди, бот показывает место.
- После успешной отправки запоминается `file_id` для пары «видео +
  качество»; повторный запрос отдаётся мгновенно без скачивания (и
  списывается как обычное скачивание).
- Временные файлы удаляются после отправки и при ошибке.
- Ошибки переводятся в понятные сообщения: видео недоступно, приватное,
  слишком длинное, сайт не поддерживается.

### Данные (SQLite)

- `users`: id, дата регистрации, купленные скачивания, срок безлимита,
  бесплатных использовано и за какую дату, согласие с условиями.
- `orders`: номер, пользователь, тариф, способ, сумма, статус, время
  создания и оплаты, идентификатор платежа Telegram.
- `downloads`: пользователь, сайт, идентификатор видео, качество,
  размер, чем оплачено, время.
- `file_cache`: сайт + идентификатор видео + качество → `file_id`.

### Правовая сторона

В `/start` и `/terms`: пользователь скачивает только то, на что имеет
право, и отвечает за использование сам. Администратор может запретить
конкретное видео или пользователя командой (`/block`).

### Развёртывание

`docker-compose.yml` с тремя сервисами: бот, `telegram-bot-api`, Caddy.
Файл `.env.example` со всеми переменными и `README.md` с пошаговой
инструкцией: создание бота в BotFather, включение оплаты звёздами,
настройка магазина Robokassa (Result URL, пароли), запуск.

## Что остаётся исполнителю

- Раскладка модулей и точные названия.
- Тексты сообщений бота (в одном файле, чтобы владелец мог править).
- Набор тестов: учёт скачиваний, однократное зачисление, подпись
  Robokassa, проверка ссылок — обязательно; остальное по усмотрению.

## Что считается готовым

В этой сессии нет токена, сервера и магазина, поэтому результат — код,
тесты и инструкция в репозитории, а не работающий бот. Автотесты
покрывают учёт, зачисление, подпись и проверку ссылок; реальное
скачивание проверяется на общедоступном ролике, если сеть сессии это
позволяет. Отправка файлов до 2 ГБ, настоящая оплата звёздами и
уведомление Robokassa проверяются владельцем по списку приёмки в
`README.md` после развёртывания.

## Что понадобится от владельца для запуска

Токен бота от BotFather, `api_id`/`api_hash`, VPS за границей, домен,
магазин в Robokassa (нужна самозанятость или ИП), имя бота, ссылка на
BolBiBot для кнопки, при желании канал для обязательной подписки.
